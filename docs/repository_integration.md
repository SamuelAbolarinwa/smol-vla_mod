# Proposed repository integration

The supplied local tree contains the original extractor and tokenizer but no implementation files for language encoding, fusion or the action policy. The overlay supplies these modules, validation scripts and the experiment notebook collection.

## Proposed retained structure

- `src/smol_vla_mod/`: current Python implementation, including legacy tokenizer compatibility.
- `tests/`: existing extractor and tokenizer tests.
- `scripts/`: standalone pretrained-integration and flow-policy validation scripts.
- `Notebooks/validation/`: current component checks.
- `Notebooks/data/`: dataset preparation.
- `Notebooks/training/`: learning checks and training experiments.
- `Notebooks/evaluation/`: pilot and diagnosis experiments.
- `Notebooks/archive/`: five earlier versions retained for provenance.
- `docs/notebook_guides/`: one Markdown guide per workflow notebook.
- `docs/figures/`: editable architecture SVG.
- `reports/handover_evidence/`: compact experiment summaries.

Existing design documents may describe planned depth supervision or earlier architecture variants. Retain them as historical design records until their contents have been reconciled with `docs/project_handover.md`. Existing project configuration is deliberately not replaced by the overlay.

## Review before merging

Check the local branch, Git status and differences before copying overlay files into repository paths. Compare existing source and tests rather than assuming the provided tree describes their contents. Merge ignore rules into the existing ignore file. Remove generated bytecode and cache directories only after checking whether Git tracks them. Review the final staged diff and exclude model weights, datasets, environments, credentials and outputs. Exact commands and the push destination will be prepared after the user shares the extracted state and Git information.

## Notebook maintenance

The current notebooks remain standalone Kaggle snapshots with embedded source. Importable repository source and notebook snapshots may diverge in future edits; both should be updated and verified when implementation changes. The clean-up in this package changes notebook narrative and clears outputs while preserving code. It does not refactor experiments or establish new numerical results.

The initial small-data and extended-overfit notebooks remain in training because they document different budgets and checkpoint progression. The earlier CLIP and closed-loop environment versions are archived because newer entry points supersede them.
